TECHNICAL WRITING / GIT

Git Installation and Notepad++ Setup for Writers' Workflow

February 16, 2025 · Princy Victor

Git is a version control system widely used in software development to track changes in files over time. It allows multiple people to work on a project in parallel, keep track of edits, revert to previous versions, and more. Although Git is widely used in software development, it is also a useful system for documentation management.

In this article, I explain how Git works and how technical writers can use it in their documentation workflow. The examples in this article use Windows.

How Git works

Working directory

The working directory is the location where you make changes to your files. Files in this location can be untracked, such as new files, or modified files that Git already knows about.

Staging area

Changes made in the working directory are moved to the staging area when you execute the git add command. This does not permanently save the changes.

Local repository

Changes added to the staging area are saved to the local repository when you execute git commit. The local repository is stored in the .git directory inside your project. A commit saves changes only to your local repository; it does not share them with others.

Remote repository

A remote repository is stored on a server such as GitHub, GitLab, or Bitbucket. Changes saved in your local repository are shared with the remote repository when you execute git push. You can retrieve changes from the remote repository using git pull or git fetch.

Common Git terms

Branch
An alternate line of development where you can try new ideas without changing the main project.
Merge
Combines changes from different branches.
Commit
Takes a snapshot of your work and saves it to the local repository.
Clone
Downloads a copy of another project so you can work on it locally.
Push
Sends commits from your local repository to a shared remote repository.
Pull
Fetches the latest changes from a shared remote repository and integrates them into your local branch.

Install Git for Windows

Download Git for Windows from the official Git website. After installation is complete, verify it from PowerShell or the command prompt: 

git --version

Set up a local repository

Configure your identity

Open PowerShell or the command prompt and configure your name and email address:

git config --global user.name "Your Name"
git config --global user.email "your.email@example.com"

Verify the configuration with:

git config --list

This guide keeps Git's default branch name unchanged. You can configure a different default branch name if your team's workflow requires it.

Select Notepad++ as the text editor

If you prefer Notepad++ to editors such as Vim or Nano, configure Git to open files with Notepad++: 

git config --global core.editor "'C:\Program Files\Notepad++\notepad++.exe'"

Create a local repository

Suppose you want to create a repository called myhellogitrepo. First, create the directory in a location of your choice. Then navigate to it in the command prompt and initialize the repository: 

git init

Git creates a new .git directory inside myhellogitrepo. Your local repository is now ready for files and commits.

Set up a remote repository

  1. Create or sign in to your GitHub account.
  2. Select the + icon in the top-right corner and choose New repository.
  3. Enter the repository details and select Create repository.

Connect your local repository to the remote repository:

git remote add origin <link-of-your-repository>

Add files to the remote repository

Create a file such as sample1.txt inside myhellogitrepo. Check its status: 

git status

A new file appears as untracked. Stage the file with: 

git add .

Verify that the changes are staged:

git status

Save the staged changes to your local repository:

git commit -m "Add sample file"

Finally, push the commit to GitHub:

git push -u origin master

You can now see the file in the remote repository. You have successfully moved a file from your working directory to a shared GitHub repository.

Git provides technical writers with a reliable way to manage documentation versions, collaborate with development teams, review changes, and maintain a clear history of edits.
